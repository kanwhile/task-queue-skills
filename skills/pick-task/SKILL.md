# Pick task

อ่าน `config.md` และ `trackers.md` ในโฟลเดอร์สกิลนี้ก่อน · config ไม่ครบ = หยุดตามที่ `config.md` บอก
`<TASKS>` = `<root>/.tasks` · `<root>` ตาม `config.md` · `<acct>` = จาก `บัญชี` หรือ `budget-check --pick` · ไม่มี `budget-check` → ข้ามทุกขั้นที่เรียกมัน ตาม `config.md`
ไม่ได้รับ `<ref>` → อ่านคิวตาม `trackers.md` แล้วหยิบใบบนสุดที่ไม่ถูก Blocked by
argument `--model <id>` = โมเดลที่ `/run-task-queue` เลือกให้ session นี้ตาม rubric ของ config · เขียนลงบรรทัด `โมเดล:` ที่หัว `task.md` ตอนสร้างไฟล์ (การ์ดเดิมที่มีไฟล์แล้วไม่แก้) เพื่อให้รอบแก้รีวิวใช้โมเดลเดิม

## เลือกโหมด
หา `task.md` ของการ์ดด้วย `grep -l "<ref>" <TASKS>/*/task.md` (Notion ใช้ id 32 หลักของหน้า)
- ไม่เจอ หรือสถานะในไฟล์เป็น "กำลังทำ" / "หยุดเพราะโควตา" / "มีคำถาม" → **ทำการ์ด**
- สถานะ "เปิด PR แล้ว" → **แก้ PR**

## ทำการ์ด
ก่อนข้อ 1, 5, 7 และ 9 เช็กโควตาตามหัวข้อ "เช็กโควตา"

1. เปลี่ยนสถานะการ์ดเป็น `in-progress`
2. อ่านการ์ดตาม `trackers.md` ให้ครบทั้งรายละเอียดและ Acceptance Criteria
   ถ้าเจอ `task.md` ให้อ่านทั้งไฟล์ก่อนทำอย่างอื่น โดยเฉพาะ "โน้ตจากเจ้าของ" และ "ขั้นต่อไป"
3. การ์ดที่ยังไม่มี issue (เฉพาะ kind ที่การ์ดกับ issue แยกกัน): ตัดสินเองว่าควรเปิดไหม ตาม `trackers.md`
4. ห้ามทำงานใน checkout หลัก เพราะเจ้าของอาจมี branch ที่ยังไม่ commit และ dev server เปิดค้างอยู่ในนั้น
   - เจอ `task.md`: ทำต่อจาก branch กับ worktree ที่หัวไฟล์
     worktree ยังอยู่ใน `git worktree list` → `EnterWorktree` ด้วย `path` นั้น
     ไม่อยู่แล้ว → `git worktree add .claude/worktrees/task-<เลข> <branch>` แล้ว `EnterWorktree` ด้วย path ใหม่ และแก้ path ที่หัวไฟล์
     จากนั้นทำแค่ bullet `setup` แล้วเริ่มจาก "ขั้นต่อไป" ในไฟล์
   - การ์ดใหม่: `EnterWorktree` สร้าง worktree ชื่อ `task-<เลข>` ซึ่งแตก branch จาก `origin/<default>`
   - ทำตาม `setup` ของ config (ห้ามแตะไฟล์ env ของ checkout หลัก)
   - เปลี่ยนชื่อ branch ตาม `branch` ของ config
   - สร้าง `<TASKS>/<ชื่อ branch ตัด prefix/ ออก>/task.md` จาก `task-template.md` ในโฟลเดอร์สกิลนี้
     ใส่หัวไฟล์ AC และรายละเอียดจากการ์ดให้ครบ พร้อมดาวน์โหลดไฟล์แนบลง `assets/`
     เพราะ delegate อ่านบอร์ดไม่ได้ ทุกอย่างที่ต้องใช้ทำงานต้องอยู่ในโฟลเดอร์นี้
5. ทำแบบ TDD ด้วยสกิล `tdd` ถ้ามี ไม่มีก็วน red → green ทีละ slice เอง
   **seam**: ก่อน test แรก เขียนรายการ seam ที่จะ test ลง "การตัดสินใจ" ใน `task.md` (AC ระบุ seam ไว้ให้ใช้ตาม AC)
   รายการนี้คือ seam ที่ตกลงแล้วที่ `tdd` ให้ confirm กับคน เพราะ session นี้ไม่มีคนตอบ · เจ้าของแย้งได้ทาง "โน้ตจากเจ้าของ"
   ระหว่าง slice รันแค่ typecheck กับไฟล์ test ที่แตะ · test ชุดเต็มรันครั้งเดียวในข้อ 7
   test ที่ seam Claude เขียนเองเพราะเป็นตัวตัดสินว่างานเสร็จ (`ROUTE-EXTERNAL` ให้ delegate เขียนตามรายการ seam ได้ แต่ Claude ต้องเห็น test red ก่อนส่งงานโค้ดต่อ)
   โค้ดที่ทำให้ test ผ่าน งานไล่อ่านโค้ด ค้นไฟล์ หรือแก้หลายไฟล์ ส่งต่อตามหัวข้อ "ส่งงานให้ delegate" แล้ว Claude รันไฟล์ test นั้นเองหลังงานกลับมา
6. ทำตาม `กฎโค้ด` ของ config
7. รัน `verify` ของ config ให้ผ่าน และปิดของที่เปิดเองตามที่ config บอก
8. เปิด PR เข้า `<default>` ถ้ามี issue ให้ใส่ `Closes #<เลข>` (คำว่า Closes ต้องนำหน้าทุกเลข)
9. ทำตาม `self-review` ของ config แล้วแก้ทุกข้อที่ต้องแก้ก่อน push
   `self-review` ใช้สกิล `code-review`: ส่ง fixed point `origin/<default>` และ spec เป็น path เต็มของ `task.md` ไปด้วย จึงไม่ต้องใช้ `docs/agents/issue-tracker.md`
   smell จาก baseline ของสกิลเป็นดุลยพินิจ แก้เองในข้อนี้หรือข้ามพร้อมเหตุผลใน PR body ไม่นับเป็นข้อให้เจ้าของตัดสิน
   ข้อที่ต้องให้เจ้าของตัดสิน: config มีหัวข้อ `merge` และ PR ไม่แตะ `.claude/task-queue.md` หรือ path ที่ขึ้นต้นด้วยค่าใน `ไม่ auto:` (`gh pr diff <n> --name-only`) → คัดตามหัวข้อ "แยกคำถาม" ก่อน
   ข้อที่เหลือเขียนกลับการ์ดใต้ `## รอเจ้าของตัดสิน` เป็นตัวเลือก ก/ข/ค พร้อมผลของแต่ละทาง และบอกว่าแนะนำทางไหน
   ตรา (ข้อ 12) โพสต์หลังคัดเสร็จเสมอ แม้ `self-review` ของ config จะสั่งให้โพสต์ระหว่างรีวิว เพราะตราแรกที่ n > 0 ทำให้ PR ไม่ถูก merge อัตโนมัติอีกเลย
   จบข้อนี้เมื่อทุกข้อที่ต้องแก้มี commit แล้ว หรืออยู่ใต้ `## รอเจ้าของตัดสิน` หรืออยู่ในการ์ด `ตัดสิน:`
10. ทำตาม `ci` ของ config จนเขียว
11. ทำตาม `หลัง PR` ของ config
12. comment **ตรา** (ตาม `trackers.md`) ลง PR ถ้า comment ตราล่าสุดยังไม่ชี้ head ปัจจุบัน (ไม่มีเลย หรือ ci ต้อง push แก้หลังรีวิวตัวเอง) หรือขาด `· แยกคำถามไป <ref>` ทั้งที่ข้อ 9 สร้างการ์ด `ตัดสิน:`: ``ส่งเจ้าของ (head `<sha>`) · รอเจ้าของตัดสิน <n> ข้อ`` ต่อท้าย `· แยกคำถามไป <ref>` เมื่อมีการ์ดนั้น
    หลังจากนี้ห้ามโพสต์อะไรลง PR อีก ข้อมูลเพิ่มให้แก้ PR body แทน เพราะ `/run-task-queue` จะไม่ merge PR ที่มี comment หลังตรา
13. เปลี่ยนสถานะการ์ดเป็น `in-review` · เขียนกลับลิงก์ PR ตาม `trackers.md` · ตั้งสถานะใน `task.md` เป็น "เปิด PR แล้ว (#<เลข PR>)"
    `/run-task-queue` ใช้ PR ที่หาเจอจากการ์ดตัดสินว่างานค้างอยู่ไหม การ์ดที่หา PR ไม่เจอจะถูกนับว่าหลุด

รายละเอียดในการ์ดไม่ชัด หรือต้องตัดสินใจเรื่อง product: อย่าเดา
เขียนคำถามกลับการ์ดใต้ `## คำถาม` แล้วเปลี่ยนสถานะเป็น `unclear` (`/run-task-queue` ใช้สองอย่างนี้ตัดสินว่าปิด tab ได้)
มี `task.md` แล้ว: ตั้งสถานะในไฟล์เป็น "มีคำถาม" และเขียน "ขั้นต่อไป" ให้ทำต่อได้ เจ้าของตอบแล้วย้ายการ์ดกลับเป็น `queued` รอบหน้าจะเจอ `task.md` แล้วทำต่อตามข้อ 4

## แยกคำถาม
ใช้ในข้อ 9 เพราะ PR ที่ตรามี n > 0 ไม่ถูก merge อัตโนมัติ และนับเป็น PR เปิดค้างจนคิวหยุดหยิบการ์ดใหม่
ถามทีละข้อ: **ถ้าเจ้าของไม่ตอบเลย merge โค้ดตามทางที่แนะนำได้ไหม**
- ได้ (เลือกผิดแล้วแก้ทีหลังได้ · เรื่องขอบเขต · งานต่อยอด) → **แยก**: implement ทางที่แนะนำลงใน PR นี้ให้เสร็จ แล้วย้ายข้อนั้นไปการ์ด `ตัดสิน:`
- ไม่ได้ (merge แล้วขึ้น environment ที่เสียของถ้าเลือกผิด · ย้อนยาก · แตะข้อมูล สิทธิ์ หรือความปลอดภัย) → **บล็อก**: เขียนใต้ `## รอเจ้าของตัดสิน` ตามข้อ 9
- ไม่แน่ใจ = บล็อก

มีข้อแยกอย่างน้อย 1 ข้อ → สร้างการ์ด 1 ใบต่อ PR ด้วย "สร้างการ์ด" ของ `trackers.md`:
- ชื่อ `ตัดสิน: <ชื่อการ์ดต้นทาง> (PR #<n>)` · สถานะ `unclear` · Priority เดียวกับการ์ดต้นทาง
- เนื้อการ์ดต้องพร้อมให้ทำต่อเมื่อเจ้าของย้ายเป็น `queued` เพราะ pick-task รอบนั้นจะทำเหมือนการ์ดใหม่ แตก branch จาก `<default>`:
  ลิงก์ PR และการ์ดต้นทาง · แต่ละข้อมี คำถาม · ตัวเลือก ก/ข/ค พร้อมผล · ทางที่ implement แล้วใน PR นี้ · ถ้าเลือกทางอื่นต้องแก้ไฟล์ไหนอย่างไร
- ปิดท้ายเนื้อด้วยวิธีตอบ: เห็นด้วยกับทางที่ทำไปแล้วทุกข้อ → ปิดการ์ด · อยากเปลี่ยนข้อไหน → เขียนคำตอบลงการ์ดแล้วย้ายเป็น <ชื่อจริงของ `queued` จาก `สถานะ`>

จากนั้นเขียนกลับการ์ดต้นทางใต้ `## รอเจ้าของตัดสิน` บรรทัดเดียว `แยกคำถาม <จำนวน> ข้อไปที่ <ref ใหม่>` · ใส่บรรทัดเดียวกันใน PR body · ตราในข้อ 12 ต่อท้าย `· แยกคำถามไป <ref ใหม่>`

## แก้ PR
1. อ่าน `task.md` ทั้งไฟล์ · เข้า worktree ตามข้อ 4 ของ "ทำการ์ด" (bullet แรก) · เช็กโควตา
2. ดูสุขภาพ PR ตาม `trackers.md` · `DIRTY` → ข้อ 3 · `CHANGES_REQUESTED` ที่ยังไม่แก้ → ข้อ 4 · เป็นทั้งคู่ → 3 แล้ว 4 · ไม่เป็นทั้งคู่ → บันทึกใน `task.md` แล้วจบ
3. conflict: `git fetch origin && git merge origin/<default>` แก้ด้วยสกิล `resolving-merge-conflicts` ถ้ามี · ห้าม rebase และห้าม force-push · รัน `verify` ให้ผ่าน
4. รีวิว: อ่านข้อความรีวิวทุกชนิดที่มาหลัง commit ล่าสุดของ branch (ตาม `trackers.md`) แล้วแก้ทุกข้อ
   ข้อที่เห็นต่าง: ตอบเหตุผลใน thread นั้น และเขียนลงการ์ดใต้ `## รอเจ้าของตัดสิน` แบบเดียวกับข้อ 9 ของ "ทำการ์ด"
   รัน `verify` ชุดที่เกี่ยวกับข้อที่แก้
5. push · ทำตาม `ci` ของ config · ตอบทุก inline thread ที่แก้ · แล้วปิดท้ายด้วย comment สรุปซึ่งเป็น **ตรา** (ตาม `trackers.md`) และต้องเป็นสิ่งสุดท้ายที่โพสต์ลง PR:
   ``แก้รอบรีวิว (head `<sha>`) · แก้ n ข้อ · รอเจ้าของตัดสิน n ข้อ`` · แก้ conflict อย่างเดียวใช้ ``แก้ conflict (head `<sha>`) · รอเจ้าของตัดสิน 0 ข้อ``
6. อัปเดต `task.md` (บันทึกรอบนี้ · "ขั้นต่อไป" ใหม่ · สถานะคง "เปิด PR แล้ว") · การ์ดคง `in-review`

## เช็กโควตา

ไม่มี `budget-check` → ถือว่าได้ `OK` ไม่ต้องรันอะไร · มี → รัน `budget-check --unattended --acct <acct>` แล้วทำตามผล:

- `OK`: ทำต่อตามปกติ
- `ROUTE-EXTERNAL`: ทำต่อได้ แต่ส่งงานโค้ดให้ delegate ให้มากที่สุดตามหัวข้อ "ส่งงานให้ delegate" Claude เหลือแค่รีวิวกับ verify
- `STOP` ก่อนข้อ 1: ยังไม่มีอะไรให้เก็บ จบเลยโดยไม่แตะการ์ด
- `STOP` หลังจากนั้น: หยุดงานตรงนั้นแล้วเก็บงานให้ทำต่อได้
  1. commit ทุกอย่างลง branch ของงาน ข้อความขึ้นต้นด้วย `wip:` ไม่ push ไม่เปิด PR ไม่รัน verify
     git hook ไม่ให้ commit → หยุดแล้วเขียนบอกในการ์ด
  2. อัปเดต `task.md`: สถานะ "หยุดเพราะโควตา" · เขียน "ขั้นต่อไป" ใหม่ · เพิ่มบันทึกรอบนี้พร้อมตัวเลขจาก `budget-check` และ commit
  3. เขียนกลับการ์ดใต้ `## หยุดเพราะโควตา` แค่ 2–3 บรรทัด: หยุดก่อนข้อไหน และ path ของ `task.md` (`/run-task-queue` ใช้หัวข้อนี้ตัดสินว่าปิด tab ได้)
  4. ปล่อยสถานะเป็น `in-progress` แล้วจบ
  เจ้าของย้ายการ์ดกลับเป็น `queued` รอบหน้าจะเจอ `task.md` แล้วทำต่อตามข้อ 4

## task.md

ไฟล์ส่งต่องานระหว่าง agent อยู่ที่ `<TASKS>/<ชื่อ branch ตัด prefix/ ออก>/` ในเครื่องเท่านั้น ไม่เข้า git

- Claude ตัวที่ถือการ์ดเป็นคนเดียวที่เขียน `task.md` ส่วน delegate เขียนแค่ `reports/<ชื่อ agent>.md`
- ทุก agent อ่าน `task.md` ทั้งไฟล์ก่อนเริ่มงาน: Claude อ่านในข้อ 2 ส่วน delegate สั่งผ่าน prompt ตามหัวข้อ "ส่งงานให้ delegate"
- เจ้าของอาจเขียน "โน้ตจากเจ้าของ" เพิ่มระหว่างทาง ให้อ่านส่วนนี้ซ้ำก่อนข้อ 5, 7 และ 9 แล้วทำตามเสมอ
- จบข้อ 5, 7, 9 และตอนหยุดกลางทาง: เขียน "ขั้นต่อไป" ใหม่ให้เป็นปัจจุบัน แล้วเพิ่มบันทึกรอบนี้ต่อท้าย "บันทึกแต่ละรอบ" โดยไม่แก้บันทึกเก่า
  ใครมาทำต่อต้องเริ่มงานได้จาก "ขั้นต่อไป" ทันทีโดยไม่ต้องถามใคร
- การตัดสินใจเชิงเทคนิคใส่ใน "การตัดสินใจ" พร้อมเหตุผล การ์ดเก็บแค่สถานะ ลิงก์ PR และสิ่งที่เจ้าของต้องเห็น

## ส่งงานให้ delegate

ใช้สกิล `delegate-wave` เพื่อประหยัด token ของ Claude งานเล็กแค่ไฟล์เดียวหรือไม่กี่บรรทัดทำเองได้เลย
"งานไหนให้ใคร" และ rules เพิ่มอยู่ใน `delegate` ของ config · กติกาที่คิวพึ่งและใช้ทุก repo:

- เปิด pane ของ delegate ใน tab ตัวเอง ให้ cwd เป็น worktree ของงานนี้:
  `herdr pane split --current --direction right --cwd <path ของ worktree>`
  พอ `/run-task-queue` ปิด tab นี้ pane เหล่านี้ก็ปิดตามไปด้วย

- grok: ใส่กฎอ่าน `task.md` ไว้ใน system prompt ตอน start ด้วย `--rules` ต่อท้ายตัวเลือกอื่นหลัง `--`
  `herdr agent start wave-… --kind grok --pane <id> -- <ตัวเลือกตาม delegate-wave> --rules "ก่อนเริ่มงานทุกครั้ง อ่าน <path เต็มของ task.md> ทั้งไฟล์ แล้วทำตามโน้ตจากเจ้าของ"`
  agy ไม่มีตัวเลือกนี้ จึงพึ่งบรรทัดแรกของ prompt
- บรรทัดแรกของ prompt ทุกตัว: `อ่าน <path เต็มของ task.md> ทั้งไฟล์ และดูไฟล์ใน assets/ ก่อนเริ่มงาน`
- จากนั้น prompt ต้องสั่งให้ delegate:
  - อ่านไฟล์กฎของ repo (ตาม `กฎโค้ด`) แล้วแตะเฉพาะไฟล์ที่ระบุไว้
  - งานโค้ดของข้อ 5: เป้าหมายคือให้ไฟล์ test ที่ระบุผ่าน · test คือสเปก แก้แค่โค้ด ถ้าเห็นว่า test ผิดให้เขียนเหตุผลในรายงาน
  - เก็บการเปลี่ยนแปลงไว้ใน working tree ให้เรา commit เอง
  - ไม่รัน dev server หรือ verify เพราะจะชนพอร์ตและ state กับที่เรารันเองในข้อ 7
  - เขียนรายงานลง `<TASKS>/<งานนี้>/reports/<ชื่อ agent>.md`: ไฟล์ที่แตะ คำสั่งที่รันพร้อมผล และสิ่งที่ยังไม่เสร็จ
